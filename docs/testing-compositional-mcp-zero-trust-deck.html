08 · The seven invariants
What must hold across the whole plan, not per call
ID
INVARIANT
IN THIS DEMO
I-01
Authority never grows across hops
substitute: A's own gate refuses the widened call
I-02
Capability is not permission
gist: B lists a gist tool; no row permits it
I-03
Tokens are audience-bound
modeled on stdio: each server trusts its link
I-04
Restricted data stays out of unapproved sinks
gist, substitute: the summary never reaches the gist
I-05
Every effect has a prior decision
every run: the judge checks the order in each journal
I-06
Retries and partial failures stay safe
not run here; the effect states say unknown, not failed
I-07
The run is replayable
every run: an independent recount, 211 / 124 / 179 checks

10 · Future work
A policy engine, types and proofs for the same gate
Policy
Cedar for the rules
Rules as Cedar policies: a schema, analysable, one language for hosts and servers. The engine decides inside the gate, on the parsed bytes.
Types
Zero-cost gates in Mojo, C++ and Lean
Permit from acknowledgement, as a type in each SDK. No permit, no write: a compile-time fact, no run-time cost.
Proof
Lean from the same source
Charon and Aeneas lift the checker and the gate's ordering from the shipped Rust into Lean. Proved once, not recounted per run; fsync and the pipe stay the trust boundary.
The policy is Cedar. The permit is a type. The proof is Lean. The gate on the bytes stays.

Compositional questions
