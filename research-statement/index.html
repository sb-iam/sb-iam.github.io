Just-in-Time Abstractions for Software Using Hybrid Program Analysis

My research develops just-in-time abstractions for software: program representations that are constructed and refined incrementally as analysis requires them. The purpose is to support static verification of program properties and their validation on observed executions.

Research Area
Hybrid program analysis
Languages
C++, Rust, Lean and Mojo

Static analysis conventionally assumes a closed world, in which all of the code is present before analysis begins. The assumption fails wherever code is loaded, generated or compiled at run time. For example, in one release of Facebook for Android we found 3,918 classes by static analysis and 23,621, six times as many, after capturing three files that the app loaded as it ran. Hybrid analyses built on closed-world frameworks capture such code and then repeat the static analysis on the whole program.

Jitana and ReHAna

Jitana and ReHAna, our frameworks for hybrid program analysis on Android, remove the assumption. They combine static analysis with observation of the app as it runs, and their design is modeled on two mechanisms of a language virtual machine: the class loader, which loads a class only when it is needed, and the just-in-time compiler, which analyzes one method at a time.

Jitana's Class-Loader Virtual Machine is a virtual graph loader: it models the class loaders of the device and loads a class into its graphs only when reachability analysis or the running app requires it. Because a class is identified by its loader and its name, the classes of many apps remain distinct in one analysis (Figure F1). One such analysis covered the 129 apps on a tablet, two million methods in all, in 19 minutes.

ReHAna's Virtual Class-Loader follows the class loader of a running app. When the app loads classes through reflection or dynamic code loading, ReHAna analyzes them as they are loaded and adds the results to the existing graphs; the code already analyzed is not analyzed again. Across 21 apps, ReHAna slowed execution by a factor of at most 1.32, whereas StaDynA, an earlier hybrid analysis for the same task, slowed it by as much as 5.71.

JITAC: Just-in-Time Abstractions for Code

JITAC carries the virtual graph loader from the classes of an Android app to compiled computation. A neural network model, for example, is compiled for the hardware on which it runs, and an analysis of its source therefore misses the code that executes, as an analysis of an Android package misses the classes loaded later.

For such programs I propose a virtual incremental loader, which keeps two tasks of the virtual graph loader and adds a third.

  1. It constructs the representation of a unit of code, as nodes and edges of one program graph, only when an analysis or the running program requires that unit.
  2. It records static results and observations of an execution on the same nodes, so that what an analysis predicts can be compared with what is observed.
  3. When a unit is added or changed, it updates the analyses that depend on that unit and keeps the others; the virtual graph loader handles only units that are added.

C++, Rust, Lean and Mojo are the first-class languages of this research. VerifyD, my current platform for hybrid analysis, separates control from computation and puts a typed program graph between them (Figure F2).

Current Direction

My dissertation applies the method to neural network models compiled by MAX, a framework from Modular whose kernels are written in Mojo: static analysis predicts the behavior of an execution, the execution is observed, and the two are reconciled. The measured results in this statement are those of Jitana and ReHAna; JITAC is under construction and has not yet been evaluated, and papers on it are in preparation.
