Hybrid program analysis, verification and synthesis for the current AI infrastructure

A concise research statement connecting Android hybrid analysis, the VerifyD Platform, compiler infrastructure, and interpretable AI systems.

My research is in hybrid program analysis: combining static analysis, dynamic analysis, compiler infrastructure, and runtime evidence to understand software systems that cannot be explained by a single analysis technique.

I came to this work through Android program analysis, enterprise cloud systems, ML infrastructure, and compiler-integrated interpretability. The common thread is practical: real systems mix source code, generated code, runtime behavior, configuration, libraries, and human intent. Analysis needs to follow that mixture instead of pretending the system is closed and static.

Android Lineage

Jitana and ReHAna are the foundation of my research lineage. Jitana addressed scalable hybrid analysis for interacting Android applications. ReHAna focused on reflective code, where runtime behavior intentionally hides important targets from ordinary static analysis.

A single Jitana session can hold several large applications at once. The classloader graph below is what the analysis actually sees.

Those projects shaped how I think about software analysis. Static facts are necessary but incomplete. Runtime observations are necessary but incomplete. Useful analysis comes from composing them carefully and keeping track of what each method can and cannot claim.

VerifyD Platform

VerifyD is my current platform work for hybrid analysis of AI-assisted software development. The goal is to make software changes easier to inspect, test, explain, and review using static checks, dynamic checks, compiler-aware evidence, and provenance.

The platform separates control from computation and puts a typed program graph between them.

The platform builds on my research background in Android hybrid analysis and compiler-integrated interpretability, but it is framed around practical software-engineering workflows rather than a standalone interpretability system.

Current Direction

My current direction keeps the hybrid-analysis core and applies it to modern AI-assisted software work. I am interested in how static analysis, dynamic checks, compiler IR, and model-facing tools can help engineers understand code that is written, modified, or explained by AI systems.

The point is not to claim that a model can replace analysis. The point is to use each tool for what it is good at: models for search and explanation, static analysis for structure, dynamic analysis for behavior, compilers for semantics, and humans for judgment.
